# Code-Skill

一套给 AI 编码 agent 用的工程判断规则。核心理念只有一句：**不发明需求，不写没有检查的实现。**

规则本身是四个来源的综合：ponytail 的决策阶梯、codingskills 的可数判据、Superpowers 的行为闸门，外加两组实测暴露出来的补丁。它不是又一份"最佳实践清单"，每一条都能在一份可复跑的对照实验里找到依据，或者说明它为什么在那儿。

## 里面是什么

| 文件 | 用途 |
|---|---|
| `AGENTS.md` | 常驻规则。放到项目根目录或 `~/.dsh/AGENTS.md`、`~/.claude/AGENTS.md` 这类全局位置，每轮自动进上下文 |
| `skills/engineering-judgment/SKILL.md` | 同一份规则的 skill 版（带 frontmatter），放进 `~/.agents/skills/engineering-judgment/` 按需加载 |
| `docs/benchmark.md` | 三臂对照实验的完整数据与复跑方法 |
| `docs/provenance.md` | 每段规则的来源、上游许可证、哪些条款是实测新增 |

两种用法可以并存，但**别同时启用**：常驻版和 skill 版内容相同，同时生效等于把同样的规则喂两遍。

## 它解决什么问题

一句话需求，无规则时的产物：

```
"读 CSV，求 amount 列数值之和。文件来自第三方导出，质量不可控。"
→ 451 行代码，支持 UTF-16 编码探测、GBK 回落、分隔符嗅探、货币符号、
  千分位、会计括号负数、科学计数法、Excel sep= 指令、options 参数……
→ 其中 9 项是需求里一个字都没提的。
```

同一句话，加规则后：

```
→ 39 行，只读逗号分隔，脏值跳过，缺列报错。0 项需求外功能。
```

差 7–12 倍。而且这 450 行不只是多，它是**多错了**：它花力气测了 20 万行吞吐（791 ms），却没做对"引号内的逗号要能解析"。

## 规则管什么、不管什么

管三件事：

1. **该不该写**——7 级阶梯，从"这功能需要存在吗"一路问到"能不能一行"。
2. **怎么算过度**——用可数的判据（出现三次才抽象、从未切换过的开关就该删），不用"保持简洁"这种形容词。
3. **什么时候算完成**——先跑出本轮证据再说，包括"agent 报告成功不算证据"。

不管三件事，别指望它替你做：

- 不提升算法质量、架构品味、性能优化能力。它只减少垃圾，不生产好东西。
- 在性能关键、并发安全、硬件校准这类场景，它的"最小实现"倾向会让位给边界正确性——但这需要你自己判断，规则只写了「不参与偷懒权衡」。
- 它压不住"留检查"这一条。实测六个样本里两个没留检查。这是全套规则里执行率最低的一条，你得自己盯。

## 数据

同一任务、同一模型、prompt 对称，只有规则不同，每臂 2 次独立会话：

| 臂 | 代码行数 | 需求外发明（10 项特征） | 崩溃 |
|---|---|---|---|
| 无规则 | 451 / 479 | 9 / 9 | 0 |
| ponytail | 71 / 62 | 1 / 3 | 0 |
| 本规则 | 39 / 90 | 0 / 3 | 0 |

诚实说明：n=2，全部由 DeepSeek 执行，任务只有 CSV 求和这一个。**同一条规则内部两次跑出的差异（39 vs 90 行），比两套规则之间的均值差异（64.5 vs 66.5 行）更大**。所以能说的是"规则对无规则有数量级优势"，不能说"本规则优于 ponytail"。完整方法与局限见 `docs/benchmark.md`。

## 来源

综合并改写了三个 MIT 项目：

- [ponytail](https://github.com/DietrichGebert/ponytail) — 7 级阶梯、根因修复、`ponytail:` 天花板标注
- [codingskills](https://github.com/JordanCoin/codingskills) — 三次才抽象、删除判据、YAGNI 的四条边界、与 DRY 的冲突裁决
- [superpowers](https://github.com/obra/superpowers) — 证据闸门、调试的四阶段纪律

许可证与逐条归属见 `docs/provenance.md`。

## 一句话

这套规则最大的价值不是让你写得更少，是让你**不去实现没人要的东西**。
