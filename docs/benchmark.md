# 三臂对照实验

## 设计

| 项 | 设置 |
|---|---|
| 任务 | 同一句需求：读 CSV，返回 `amount` 列的数值之和；CSV 有表头；文件来自第三方导出、质量不可控。导出 `{ sumAmount }`，只写实现文件 |
| 臂 | A：无规则（明确要求忽略一切 YAGNI / 最小实现类规则）<br>B：ponytail 原文<br>C：本仓库规则 |
| 隔离手段 | 每次是一个独立 agent 会话（无共享上下文），三臂的 prompt 除规则条款外逐字相同 |
| 样本 | 每臂 2 次 × 2 轮 = 每臂 4 次，共 12 次 |
| 执行模型 | DeepSeek（本机 DSH 会话） |

## 测量口径与一处已修正的错误

发明项 = 10 项需求外特征的正则命中数：

分隔符嗅探、货币符号、千分位、UTF-16、括号负数、欧式小数逗号、科学计数法、BigInt/定标精度、`options` 参数、编码探测。

**关键修正**：第 1 轮的初测没有剥离注释，于是代码里"不做分隔符嗅探、不支持 UTF-16"这类**否决性注释**被正则当成了"实现了分隔符嗅探"。这个错误同时污染过两轮数据，表现是本规则臂被高估发明项（曾报 4 项，实际 1 项）。

发现路径：某次无规则臂的自述里写着"不支持分隔符嗅探"，而它的检测结果里出现了这一项——顺着这条线才查到注释被计入。

现在的实现先剥离 `//` 与 `/* */` 再做匹配。两轮数据都已按新口径重跑，上方表格是修正后的数字。**任何人复跑都应使用剥离注释的版本**，否则会复现同样的偏差。

## 安全与正确性

六组对抗输入：正常数据、空值+脏字符串混排、UTF-8 BOM、仅表头、`1,"1,5"`、无 `amount` 列。

判定：未捕获异常 = 不安全；显式 `Error` = 可接受；返回错误数值 = 记为 wrong。

十二个样本全部 0 崩溃、0 错误值。两套规则臂在脏值与缺列上都选择了显式抛错而非静默返回 0。

## 四次结论修正（保留，因为它们比结论更有用）

1. **曾认为 ponytail 在"防过度设计"上失效**——因为它的样本手写了 RFC4180 状态机。后发现无规则臂同样发明需求且更多，于是修正为：过度设计是模型的默认倾向，规则只削减规模，不改变方向。

2. **第 1 轮把基线组要求写成了"包含必要的单元测试"，ponytail 组没要求**——prompt 不对称，导致"写测试比例"那一维的结论作废。此后所有轮次三臂 prompt 严格对称。

3. **曾判定某个无规则臂的自检失败**——实际是在它写完之前读了中间产物（文件 20515 B，最终 21512 B）。复跑后 24 项断言全过，原判断撤回。教训：文件存在不等于作者收工。

4. **发明项检测把注释里的否定陈述算成实现**——见上一节。修正后本规则臂与 ponytail 臂的差距缩小到无法区分，原有"本规则发明最少"的结论作废。

## 局限

- n=4 per arm。同一条规则内部两次跑出的差异（39 vs 57 行、62 vs 90 行）大于规则之间的均值差异（68.5 vs 73.0），所以**不能**得出"本规则优于 ponytail"。
- 只有一个任务、一个模型。CSV 求和能同时暴露"边界处理"与"过度设计"，但不能代表重构、并发、性能、跨文件改动。
- 正则检测即使剥离注释，仍会漏掉换了写法但实质相同的发明，也会因命名差异误报。
- 规则里执行率最低的是"非平凡逻辑留一个能跑的检查"：十二个样本里至少一半没留下可复跑的检查（有的写了临时脚本然后删除）。

## 复跑

准备 6 个空目录，分三次各派两个独立 agent 会话，prompt 除规则条款外保持一致：

```
任务正文：读 CSV，返回 amount 列数值之和；有表头；来源质量不可控；
         导出 { sumAmount }；只写实现文件
A 臂附加：忽略一切 ponytail / YAGNI / 最小实现类规则，按默认完整工程习惯实现
B 臂附加：以 ponytail 原文为该次唯一准则
C 臂附加：（无，常驻规则自然生效）
```

判分：`node ab-eval.mjs <目录>`，统计非空非注释行数、测试文件数、10 项发明特征命中（剥离注释后）、6 组对抗输入的实际行为。
