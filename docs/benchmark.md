# 三臂对照实验

## 设计

| 项 | 设置 |
|---|---|
| 任务 | 同一句需求：读 CSV，返回 `amount` 列的数值之和；CSV 有表头；文件来自第三方导出、质量不可控。导出 `{ sumAmount }`，只写实现文件 |
| 臂 | A：无规则（明确要求忽略一切 YAGNI / 最小实现类规则）<br>B：ponytail 原文<br>C：本仓库规则 |
| 隔离手段 | 每次是一个独立 agent 会话（无共享上下文），三臂的 prompt 除规则条款外逐字相同 |
| 样本 | 每臂 2 次，共 6 次 |
| 执行模型 | DeepSeek（本机 DSH 会话） |

## 结果

| 臂 | 样本 | 实现行数 | 测试文件 | 内建自检 | 需求外发明 | 崩溃 |
|---|---|---|---|---|---|---|
| A 无规则 | 1 | 451 | 0 | 无 | 9 / 10 | 0 |
| A 无规则 | 2 | 479 | 0 | 有，24 项实跑通过 | 9 / 10 | 0 |
| B ponytail | 1 | 71 | 0 | 有，实跑通过 | 1 / 10 | 0 |
| B ponytail | 2 | 62 | 0 | 有，实跑通过 | 3 / 10 | 0 |
| C 本规则 | 1 | 39 | 0 | 无 | 0 / 10 | 0 |
| C 本规则 | 2 | 90 | 0 | 有，实跑通过 | 3 / 10 | 0 |

均值：无规则 465 行 / 发明 9 项；ponytail 66.5 行 / 发明 2 项；本规则 64.5 行 / 发明 1.5 项。

### 需求外发明检测项（10 项）

需求里只有 CSV、表头、`amount` 列、求和、来源不可控。以下每一项都是需求外的：

分隔符嗅探（`,` `;` `\t` `|` 自动选择）、货币符号与 ISO 代码、千分位、UTF-16 编码、括号负数、欧式小数逗号、科学计数法、BigInt/定标精度处理、`options` 参数、编码探测（GBK / windows-1252 回落、NFKC 全角归一）。

检测方式是对源码做关键词正则匹配，可复现，不依赖人工判断。

### 安全与正确性检测（6 组输入）

| 用例 | 内容 | 期望 |
|---|---|---|
| clean | 3 行正常数据 | 110 |
| blanks | 空值 + 非数字混排 | 60（跳过脏值）或明确抛错 |
| bom | UTF-8 BOM 表头 | 20 |
| headerOnly | 只有表头 | 0 |
| quoted | `1,"1,5"` | 不崩 |
| noColumn | 无 `amount` 列 | 明确抛错 |

判定：未捕获异常 = 不安全；显式 `Error` = 可接受；返回值错误 = 记为 wrong。六个样本全部 0 崩溃、0 错误值。

## 三次结论修正（保留，因为它们比结论本身更有用）

1. **一开始我认为 ponytail 在"防过度设计"上失效了**——因为它的样本手写了 RFC4180 状态机。后续发现无规则臂也发明需求、而且发明 9 项，于是修正为：过度设计是模型的默认倾向，规则只削减规模，不改变方向。

2. **上一轮我让基线组写了单元测试，ponytail 组没要求**——prompt 不对称，导致"写测试比例"那一维的结论作废。本轮三臂 prompt 已对称。

3. **我曾判定无规则臂 2 的自检失败**——那是我在它还没写完时读了中间产物（文件 20515 B，完成后 21512 B）。复跑后 24 项断言全部通过，原判断撤回。教训：文件存在不等于作者收工。

## 局限

- n=2。同一条规则内部两次跑出的差异（39 vs 90 行）大于两套规则之间的均值差异（64.5 vs 66.5 行），所以**不能**从本实验得出"本规则优于 ponytail"。
- 只有一个任务、一个模型。CSV 求和之所以被选中，是因为它能同时暴露"边界处理"和"过度设计"两种行为；它不能代表重构、并发、性能等场景。
- 发明需求的检测依赖关键词，会漏掉换了写法但实质相同的发明。
- 全套规则里执行率最低的是"非平凡逻辑留一个能跑的检查"：6 个样本里 2 个没留（都是短实现）。

## 复跑

准备 6 个空目录，分三次各派两个独立 agent 会话，prompt 除规则条款外保持一致：

```
目录：ab/<臂><序号>
任务正文：读 CSV，返回 amount 列数值之和；有表头；来源质量不可控；导出 { sumAmount }；只写实现文件
A 臂附加：忽略一切 ponytail / YAGNI / 最小实现类规则，按默认完整工程习惯实现
B 臂附加：以 ponytail 原文为该次唯一准则
C 臂附加：（无，规则常驻）
```

判分脚本对每个目录统计：非空非注释行数、测试文件数、内建自检是否存在并能跑通、10 项发明关键词命中、6 组对抗输入的实际行为。
